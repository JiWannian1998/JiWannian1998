# 论文雷达：不依赖 Vercel 的使用教程

## 当前发布方式

网页和公开文献索引保存在本仓库的 `paper-radar` 目录。GitHub Actions 负责采集公开元数据、生成网页和执行浏览器检查。GitHub Pages 负责对外提供网页；不需要 Vercel、商业搜索密钥、学校账号或 Altmetric 订阅。

注意：仅有仓库代码或 Actions 成功记录，不代表公网已经发布。网站地址只以仓库 **Settings → Pages** 中实际显示的 **Visit site** 为准。

## 首次开启 GitHub Pages（仓库所有者操作）

1. 打开 https://github.com/JiWannian1998/JiWannian1998/settings/pages 。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。如账户要求验证邮箱，请先完成邮箱验证。
3. 打开仓库 **Actions**，进入 **Paper Radar publish and browser acceptance**，点击 **Run workflow**，选择 `main`。
4. 查看该次运行。只有测试通过并且 **Deploy Pages** 成功，才算已发布。回到 **Settings → Pages**，点击 **Visit site** 打开真实网址。

现有集成可以更新本项目文件，但曾收到 `Resource not accessible by integration`，无法替账户所有者首次开通 Pages。不要向聊天发送密码或个人访问令牌。

## 网站使用

1. 勾选期刊。可使用“五大刊＋NBER”预设。
2. 设置论文发表窗口和关注证据窗口。两者不同：旧论文可以在最近获得报道，新论文也可能没有公开报道。
3. 点击搜索。搜索是在页面注明时间的已采集索引中进行，不是每次点击就重新访问所有出版社或知网。
4. 打开证据面板，核对来源、日期、链接和匹配依据，再访问原文。
5. 收藏候选文章，或导出 CSV / RIS。

## 更新数据

**Paper Radar refresh public index** 工作流保留了日更计划，也可从 Actions 中手动 Run workflow。日更不是实时保证；以网页的数据更新时间和来源覆盖报告为准。失败的来源不能当作“没有论文”。部分来源失败时，会保留此前实际采集的记录并标记。

## 本轮修复说明

2026-10-24 的云端诊断发现，Crossref 返回 HTTP 400 的具体原因是 `sort-criteria-incompatible-with-cursor`。已改为按发表时间过滤、游标分页不排序、在网页内排序。

NBER Digest 不再拼接不存在的月份目录地址，而改为跟随公开页面上实际存在的链接。

## 覆盖范围与未完成项

- 英文目录来自 Crossref 公开索引；索引完整不等于出版社全部内容完整。
- 关注证据目前限于 AEA Research Highlights 与 NBER Digest 的有界公开网页扫描，不是全网热度或完整社交媒体排名。
- 中文九刊全部列入选择器，不代表已全部自动接通。部分官方目录已有记录；知网全自动检索尚未完成验收。
- 知网题录检索与下载全文分开；本工具不下载收费全文、不绕过验证码或登录限制。知网题录导入只是备用，不是全自动采集。
- 方法标签来自题名摘要线索，不能代替阅读全文或因果识别质量评审。
- 本轮快速修复运行复用此前中文实采快照，报告中单独标记 `reused_snapshot`。

## 核验记录

- `diagnosis.json`：真正请求公开来源时的状态码、错误正文或题名。
- `verification.json`：逐来源取得记录数、扫描数、错误与日期范围。
- `browser-report.json`：浏览器交互及已知文献检查。
- `deployment.json`：本次发布是否取得了可访问的网址。

只有实际公网访问成功才叫上线；只有相应来源的内容验收成功才叫接通。不要把代码测试数量当作文献检索质量排名。
